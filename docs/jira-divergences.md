# Intentional Jira divergences

The 042 audit's `D`-flag ledger — places where TrackForge deliberately differs from
Jira Cloud. A divergence is a decision, not a bug; each row needs a rationale.

| # | Area | Jira behavior | TrackForge behavior | Rationale |
|---|---|---|---|---|
| D-001 | Text format | ADF (Atlassian Document Format) is canonical storage and wire format | **Markdown is canonical**; ADF exists only as a `/rest/api/3` wire format, converted at the boundary (`adfWire`); `expand=renderedFields` returns sanitized HTML | Self-hosted simplicity; Markdown diffs/greps cleanly in DB + files; see `docs/adf.md` |
| D-002 | Internal APIs | n/a | `/api/internal/*` surface alongside `/rest/api/2|3` | Frontend/agent features (boards, roadmap, automation, dev panel) that aren't Jira REST concepts |
| D-003 | Agents | Atlassian Intelligence / Rovo | MCP server with ~140 first-class tools, agent actors, proposal/approval flows, `ask_agent` automation action | TrackForge's differentiator — agents are peers with scoped permissions, not a bolt-on assistant |
| D-004 | `/search` maxResults | Cloud caps at 100 | Caps at 100 (identical) | **Parity, not divergence** — recorded here so future audits don't re-flag it; clients must page `startAt` |
| D-005 | Auth | Atlassian account, managed IdP | Local users + OIDC providers + TOTP, self-managed | Self-hosted requirement — no Atlassian account dependency; see `docs/identity.md` |
| D-006 | Deployment | SaaS-only | Single self-hosted instance, **PostgreSQL** (required — `DATABASE_URL`), periodic + durable job runner | The product's premise; `docs/deployment.md` |
| D-007 | Import | Jira↔Jira migration via cloud admin | `/migration` wizard: Jira Cloud API, Server/DC XML backup, CSV; TrackForge-native round-trip export | Self-hosted onboarding path (017/039) |
| D-008 | Notifications | Cloud mail + batched digests | SMTP templates + per-user notification scheme prefs | Self-hosted mail; scheme layer preserves Jira semantics (029) |
| D-009 | Issue keys in dev tools | DVCS connector (GitHub/Bitbucket Cloud) | Provider-agnostic signed webhook ingest + smart commits + dev panel | Works with self-hosted GitLab/Gitea — no cloud connector requirement (038) |
| D-010 | Pages without Jira counterparts | — | `/admin/migration`, `/approvals`, `/settings/ai`, `/settings/webhooks` | TrackForge-native surfaces; audited against `docs/design-system.md`, not Jira |
| D-011 | Runtime topology | DESIGN §19: separate frontend/backend services + OpenSearch | **Single-origin app image** — backend serves the built SPA at `/`, no CORS or proxy; search is SQL + JQL compiler, **no OpenSearch** | v1 self-hosted simplicity: one image, one port, `docker compose up` (043); see `docs/install.md` |
| D-012 | Navigator row open | Jira Cloud opens a right-side detail panel on row click | Row links open the full-page issue (`/browse/:key`) — Jira Server/DC + classic-navigator behavior | TrackForge's migration source is self-hosted Jira; full-page detail is the canonical surface. Cloud-style split view recorded as feature idea UB-009 (F-019) |
| D-013 | `e` shortcut | Jira opens a full edit screen | `e` enters inline edit on the issue's primary field (summary) | TF's model is pervasive inline edit — every field edits in place, so a modal edit screen is redundant; `e` keeps the muscle-memory entry point (F-038) |
| D-014 | Board card open | Jira Cloud opens a slide-in detail panel | **Now matches Cloud**: card/row click opens a slide-over drawer (`?selectedIssue=` deep-link); Ctrl/Cmd-click still routes to `/browse/:key` (058 US1 — D-014 resolved, navigator rows keep Server behavior per D-012) | Drawer is Jira Cloud's most-used interaction; keeping modifier-click preserves Server muscle memory |
| D-015 | Command palette | `.` opens Jira's actions menu; `/` = quick search | `Ctrl+K` is a **two-speed palette**: deterministic local commands (jump, assign-me, create, toggle, transition) execute with no AI round-trip, and natural-language input flows to the copilot planner | Better-than-Jira: Jira's menu is actions-only; TF's palette is actions + agent planning in one box (058 US3) |
| D-016 | Mutation feel | Every write round-trips before the UI updates | Board/backlog rank, transitions, points, assignee, flag, vote/watch apply **optimistically** with snapshot-rollback + toast on error (`src/lib/optimistic.ts` `patchIssueLists`) | Linear-class responsiveness; server stays authoritative via settle-time invalidation (058 US2) |
| D-017 | AI output | Atlassian Intelligence inserts generated text | AI drafts render as an **inline diff** with Apply (real edit path → changelog) and one-click Undo; epic breakdown creates children via bulk API with per-item `batchId` retry idempotency | Apply-don't-copy keeps attribution + audit trail; partial failures are visible and retryable (058 US4) |
| D-018 | Agent presence | Rovo is a sidebar assistant, invisible on boards | Live `running`/`blocked`/`needs-answer` badges on board/backlog cards via one bulk `/agent-activity` query + SSE invalidation; open questions answerable inline | Agents are teammates, not a chat panel — their state belongs on the work surface (058 US5) |
| D-019 | Project index | Cloud `/projects/:key` lands on a summary tab | `/projects/:key` is a five-widget **Summary** page (`GET /api/internal/projects/{key}/summary`); the issue navigator moved to the sidebar's "List" item (`/issues?jql=project = "K"`) | Jira-convergent landing + explicit navigator entry keeps Server muscle memory (058 US7) |
