# Positioning — TrackForge vs the field (Nov 2026)

"AI agents are first-class" is now claimed by everyone — Linear, Atlassian
(Rovo MCP), Plane, and several startups all say it. This doc states what is
**verifiably different** about TrackForge and what is parity or a gap. Every
claim links to proof in-repo; nothing here is aspirational.

## Verifiable differences

| Claim | Proof |
|---|---|
| Jira v2 wire-compat across the documented surface | `docs/compatibility.md` — generated by `apps/mcp/eval/compat.ts` from the live `/rest/api/2/openapi.json`; hand edits fail CI |
| Real JQL engine (not substring search) | `apps/backend/src/jql/` lexer→parser→compiler; functions incl. `ready()`, `blocked()`, `memberOf`, `linkedIssues` |
| dryRun preview on every write | `?dryRun=true` convention; tests in `apps/backend/tests/` |
| Idempotent writes | `Idempotency-Key` → `IdempotencyRecord`; replay-safe, 422 on body mismatch |
| Governance: approval policies + editable proposals | `apps/backend/src/middleware/proposals.ts`; `always` policy parks any write as a revalidatable proposal |
| Atomic ready-work claim for agent fleets | `POST /api/internal/agent/claim` — `FOR UPDATE SKIP LOCKED`; concurrency test in `tests/integration/launchWedge.test.ts` |
| Call-time (not list-time) MCP scope enforcement | readonly toolset refuses write calls; REST layer re-checks `write` scope + project allow-list per request — the failure mode in `mcp-atlassian` GHSA advisories is explicitly tested |
| Agent work loop in the product | delegate≠assignee, sessions with activities/questions, stale sweep, notifications — `apps/backend/src/services/agentSessionService.ts` |

## Parity (we do it, they do it)

- MCP server with stdio + HTTP transports — Plane, Linear, mcp-atlassian, It's a Plan.
- Per-token scopes + project allow-lists — Plane toolsets, Atlassian data policies.
- Delegation distinct from human accountability — Linear agents; `delegate` vs `assignee` is the same model.
- dryRun-style previews — nobody else ships this; counted above as a difference.

| LICENSE file | all | decision deferred — blocks public redistribution |

## Counter-positioning

- **vs Linear/Atlassian**: they own the hosted tier. TrackForge's wedge is
  self-hosted + Jira wire-compat, so existing Jira tooling (`jira` CLI,
  mcp-atlassian-shaped clients, import tools) can point at it.
- **vs Beads/Backlog.md**: repo-local, single-project, no permissions —
  perfect for solo agents. TrackForge is where the fleet goes when the JSONL
  file needs multi-project scoping, approvals, and audit.
- **vs mcp-atlassian**: a Jira *wrapper*, not a tracker — and its 2026
  advisories are the reason TrackForge tests scope enforcement at call time.
- **vs It's a Plan**: closest model (agents take work). Differences: TrackForge
  keeps Jira compat and the governance layer; it does not host the agents.
