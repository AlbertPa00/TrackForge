# Implementation Plan: Core Foundation

**Branch**: `001-core-foundation` | **Date**: 2026-06-20 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-core-foundation/spec.md`

**Note**: This plan follows the `/speckit.plan` workflow and the TrackForge Constitution.

## Summary

Build the minimal runnable foundation of the TrackForge platform: a monorepo with a backend API and a web frontend that supports creating projects, creating issues, viewing issues, and performing simple status transitions. The sprint focuses on a small, Jira-compatible data model and API surface, with automated tests covering the happy paths and primary error paths.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 20+

**Primary Dependencies**:
- Backend: Express, Prisma ORM, Zod
- Frontend: React 18, Vite, Tailwind CSS, TanStack Query, React Router
- Testing: Vitest, Supertest, Playwright
- Tooling: pnpm, Turborepo, ESLint, Prettier

**Storage**: SQLite for local development; PostgreSQL schema verified via Prisma.

**Testing**: Vitest (unit + integration), Supertest (API), Playwright (e2e smoke test).

**Target Platform**: Web browser + server running on Linux/macOS/Windows via Docker Compose.

**Project Type**: Web application with separate backend and frontend packages.

**Performance Goals**: API endpoints respond in under 500ms for typical operations; page loads in under 2 seconds.

**Constraints**: Minimal dependencies; no Redis, OpenSearch, or BullMQ for this sprint. No authentication/authorization.

**Scale/Scope**: Single-instance, tens of projects and hundreds of issues in local/CI testing.

## Constitution Check

- [x] Sprint-First Delivery: The deliverable is a runnable app with project and issue CRUD, not a partial scaffold.
- [x] API-First Design: Every feature is exposed via REST before UI consumes it.
- [x] Test-First Quality: Unit and integration tests are required for domain logic and API endpoints.
- [x] Jira Compatibility: API responses use Jira-style field names and shapes; endpoints mirror Jira REST patterns where applicable.
- [x] Explicit Simplicity: Infrastructure dependencies are deferred; only the packages needed for this sprint are introduced.
